## 3. Images
Today (verified): `ExternalServer.imageUrl` is never set by any ingest (0 rows). Owner images: `PublicListingMeta.imageUrl` is an https URL typed by the owner (`validHttpsUrl`), approved by an admin (`mediaApproved`), then HOT-LINKED in `card()` as `<img src=remote referrerpolicy="no-referrer">` (`app/nxm/_data/server-directory.ts`). No upload pipeline exists for directory images (public/ has only repo-static art; `board-uploads/` is the admin kanban, not reusable). Every external card uses the game hero.
Proposal, by tier (card shows the best available, never a broken image):
1. Owner-uploaded banner (Nxeon-hosted/claimed listings): replace "paste a URL" with upload (jpg/png/webp, <=2 MB) into the pipeline below; keep URL field but fetch+re-host it (no more hot-link); keep `mediaApproved` review.
2. Server's own icon from the protocol, re-hosted: Minecraft SLP `favicon` (64x64 PNG data URI), Rust `headerimage`/`logoimage` rule via A2S_RULES (D3), FiveM `iconVersion`/icon from `/single`, Vintage Story none, Valheim/PZ/CS2/gmod none. Source-provided images are fetched ONCE at ingest/enrich, not on page render.
3. Map thumbnail: only where we own art: curated set under `public/directory/maps/<game>/<map>.webp` for the top CS2/TF2/L4D2 maps (maps named in A2S). Start with the 20 most common map names per game (query: `select map,count(*) ... group by 1 order by 2 desc`). No Valve/third-party map images unless owner licenses them.
4. Generated per-server card art (always available, makes cards visually distinct): deterministic SVG/CSS from `hash(connKey)`: game hero as base, tinted with a hue derived from the hash, country flag chip (`/flags/xx.png`, 113 files present), game glyph (`GAME_DISPLAY[].glyph`), initials of the server name. Render in CSS (gradient + `mix-blend`), no extra files. This replaces "same hero for 994 cards".
5. Game hero/poster stays for game tiles and as the dimmed base of the generated art.
Image pipeline (new `lib/directory-images.ts`, called by an `enrich` worker step, never by a request):
- Accept only `data:image/png|jpeg|webp;base64` from protocols, or http(s) URLs from owner fields.
- SSRF-safe fetch: resolve DNS first, refuse non-public IPs (reuse `isPublicIpv4` from `lib/directory-liveness.ts`; add IPv6/IPv4-mapped refusal), pin the resolved IP for the connection, no redirects (or max 2 re-validated), https only, port 443/80 only, 5 s timeout, 2 MB cap streamed (abort at cap), `Content-Type` ignored in favour of magic-byte sniffing (PNG/JPEG/WebP only; reject SVG, GIF animations, ICO, anything else), decode with `sharp` (check it is already a dependency; else add) which rejects malformed files and strips metadata, limit input pixels (e.g. 4096x4096), re-encode to WebP at 640x320 (banner) and 96x96 (icon), content-hash filename.
- Storage: new `public/uploads/directory/<hash>.webp` is wrong for a build-replaced `public/` on promote (inferred: promote rebuilds the tree). Store under a persistent dir outside the repo (e.g. `/var/lib/nxeon/directory-images/`) and serve through a route handler `app/api/dir-img/[hash]/route.ts` with `Cache-Control: public, max-age=31536000, immutable`, nginx can cache. Table `DirectoryImage{hash pk, kind, bytes, w, h, sourceHost, createdAt, lastUsedAt, status ok|rejected}`; `ExternalServer.imageUrl` stores `/api/dir-img/<hash>`. Prune unreferenced images weekly. Per-source budget: <=1 fetch per server per 7 days, 30 fetches/min global.
- Moderation: every third-party image is pHash/size-checked, hidden behind admin review queue in `/admin/directory` before the first public display for owner-uploaded ones (as today); protocol icons auto-approved only if 64x64 and Minecraft (low risk, still reportable).

## 4. Descriptions
Where real text exists: Minecraft MOTD (SLP `description`, may be JSON chat components with `§` codes), Bedrock MOTD, Rust rules (`description_00..description_NN`, `headerimage`, `url`) via A2S_RULES (D3), FiveM `vars.sv_projectDesc`, `sv_projectName`, `tags` (via `/single`), Vintage Story `gameDescription`, PZ/ARK/Conan server name suffix and `gametype` tags, TruckersMP none (official fixed copy), Nxeon owner `publicDescription`/`tagline`/`PublicListingMeta`.
`sanitizeDescription(raw, {max=280})` (new, pure, in `lib/directory-text.ts`, unit-tested with a hostile corpus):
1. Flatten JSON chat components; strip `§x` / `&x` Minecraft codes (only when followed by [0-9a-fk-or]), Unity rich text `<color=..>`, BBCode `[b]`, HTML tags + entities (decode then strip), zero-width / bidi override characters (U+200B-200F, U+202A-202E, U+2066-2069), controls, emoji runs > 3.
2. Remove URLs/domains/Discord invites/IPs/emails (we show our own join info; avoids ad injection and phishing). Replace with nothing; if text then < 20 chars, drop it entirely.
3. Collapse whitespace, truncate at word boundary to 280, no trailing partial entity.
4. Run abuse filter (section 7). Result stored in `description` (new column `descriptionSource: motd|rules|owner|derived`).
5. Render as plain text (React escaping / `esc()`), never `dangerouslySetInnerHTML`, never markdown.
Fallback copy rule (never invent claims): when no real text, build a factual line ONLY from stored fields, exactly: `{Game} server in {Country}. {map ? "Map: "+map+". " : ""}{maxPlayers ? maxPlayers+" slots. " : ""}{parsedTags.join(", ")}`. No adjectives ("great", "friendly", "active"), no uptime/population claims that are not fresh data, no "PvP/Vanilla/Modded" unless parsed from a tag. Parse game tags into labelled chips with per-game parsers (`lib/directory-tags.ts`): Rust (`mpN` max players, `cpN` current, `pve`, `weekly/biweekly/monthly` wipes, `vanilla/modded`, `born<unix>` = last wipe time, `v2634` = protocol, region `$r?`), PZ (`modded;pvp;hidden`), Valheim (`g=1.0.16` game version, `n=` player count), CS2/TF2/gmod `gametype` tokens (`increased_maxplayers`, `nocrits`, `bots`), Conan/ARK keywords. Anything not recognized is dropped, never shown raw. Valheim `version` `1.0.0.0` placeholder: treat as null and use `g=` tag.

## 5. UX overhaul and information architecture
Audit of current page (from code, no screenshots taken to stay clear of prod builds): public NXM page is one template for 3 views: hero, featured shelf (Nxeon only, empty today), game tiles (by `groupByGame`, only games with rows), a single chip row (Nxeon / Public lists / With picture), one search box (client-side `data-q` substring on 24 home / 120 game cards, `CAP_HOME`/`CAP_GAME`), grid of identical cards, attribution, steps, FAQ. Problems: cap 24/120 means the DB's 5,883 rows are unreachable; search only searches what is rendered; no country/continent/sort/pagination; no detail page (cards link nowhere for external rows); one hero image per game; "No description" sameness; portal ships all rows to the browser and filters client-side (`filterRows`); no URL state; no favourites; thin game pages are noindex (`indexableGamePage` needs 3 described rows, today 0 external rows are described so almost all game pages are noindex).

### 5.1 Route tree (public; NXM site; sitemap entries per level, `noindex` until >= N servers)
```
/game-servers/directory                          HOME (curated landing)
/game-servers/directory/games                    all-games index (grid of every offered game, incl. 0-server ones)
/game-servers/directory/<game>                   GAME page (filters, sort, region tabs, pagination)
/game-servers/directory/<game>/<region>          GAME + REGION: <region> is a continent slug (europe, asia, north-america,
                                                 south-america, oceania, africa) OR a country slug (singapore, germany, ...)
/game-servers/directory/server/<id>              SERVER DETAIL (id = stable short id, e.g. "rust-s-8f3a1c-sg-2x-vanilla")
/game-servers/directory/country/<cc>             all games in one country (optional Phase 4)
/game-servers/directory/favourites               MY FAVOURITES (client-rendered from localStorage, noindex)
/game-servers/directory/submit                   claim/submit a listing (Phase 5)
/servers, /servers/<subdomain>                   existing free-Minecraft view, unchanged
```
Slug rules: `<game>` = GAME_FAMILIES key (existing); region slugs from `CONTINENT_LABELS`/Intl country names, a table `lib/directory-regions.ts` mapping slug <-> ISO-2, 404 on unknown, canonical = country over continent when both could apply, 301 from alias forms. Detail id: `<game>-<10-hex of sha1(connKey)>` (never expose internal cuid or the DB row id; stable across re-ingest because `connKey` is stable); slug text after is cosmetic and 301-corrected.
Portal twin: same tree under `/dashboard/directory`, `/dashboard/directory/<game>`, `/dashboard/directory/<game>/<region>`, `/dashboard/directory/server/<id>`, `/dashboard/directory/favourites`; one shared set of server components + data functions (`lib/directory-query.ts`), two skins (NXM html-string for marketing, `components/nx/Directory*.tsx` for portal). Portal differences: Nxeon-hosted servers show region/latency from the customer's own nodes, "Add to my server list"/"Deploy a server for this game" CTA, favourites synced to the account (new table `DirectoryFavourite{userId,serverKey}`) instead of localStorage, and no SEO copy.

## 6. Data model, performance, scale (20k-100k rows)
Current constraint: `externalEntries()` loads up to 600 (1000 with the regions branch) rows with Prisma `findMany`, merges in memory with Nxeon entries, dedupes, ranks, ships all to the page. That cannot scale.
New architecture: `lib/directory-query.ts` runs SQL for pagination + facets; Nxeon-hosted entries (tens) are merged in memory as a pinned/featured set (they are few) and never paginated against.
Schema (additive only; one migration, apply with the repo's safe-migration process, never `db push --accept-data-loss`):
- `ExternalServer` add: `continent String?` (derived from country at write; index), `descriptionSource String?`, `imageHash String?`, `iconHash String?`, `shortId String @unique` (sha1(connKey) first 10 hex), `slug String?`, `facets Json?` (parsed tags: `{wipe:"weekly",pvp:true,modded:false,gamemode:"..."}`), `nameLower String?` (or use `pg_trgm`), `ownerClaimId String?`, `submittedBy String?` (source=submitted), `flaggedAt DateTime?`, `reportCount Int @default(0)`, `peakPlayers24h Int?`, `languages String[]` (optional, from tags). Make `players`/`maxPlayers`/`lastAliveAt` the current values; history in a new table.
- Indexes (all `CREATE INDEX CONCURRENTLY`): `(game, hidden, blockedReason, probeStatus, country)`, `(game, continent, players DESC NULLS LAST)`, `(country, game)`, partial `WHERE hidden=false AND "blockedReason" IS NULL AND "probeStatus" <> 'DEAD'` on `(game, players DESC)` (the public set), `(firstSeenAt DESC)`, GIN on `facets` (jsonb_path_ops), `pg_trgm` GIN on `lower(name)` for search (`CREATE EXTENSION pg_trgm` needs owner OK: D9; fallback `to_tsvector`), unique `shortId`.
- `DirectoryFacetCache(key pk, game, payload Json, computedAt)`: per game + (game,region) facet counts, refreshed by the worker after each ingest or every 5 min via `GROUP BY game, continent, country` (one query for the whole home page). Pages read the cache, so home/game load = 1-2 indexed reads.
- `DirectoryStatSample(serverId, at, players)` hourly for servers with players>0 or favourited/viewed (sparkline, "trending"): <= 20k rows/h worst case; keep 14 days raw (prune job), then daily peak only. Phase 4, optional.
- `DirectoryReport(id, serverId, reason, detail, ipHash, createdAt, status)`; `DirectoryClaim(id, serverId, userId, token, verifiedAt, method)`; `DirectoryFavourite`.
Serving: public pages stay `force-dynamic` today; change list/game/region pages to ISR (`revalidate = 300`) with `unstable_cache` tags per game (`dir:<game>`), revalidated by the worker after each ingest (call a signed `/api/internal/revalidate`). Request-dependent bits ("near you", favourites) are client-fetched from `GET /api/directory/near?cc=` and `POST /api/directory/cards`, rate-limited and CDN-cacheable per cc. Detail pages ISR 60 s. API list endpoint: `GET /api/directory/servers?game&continent&country&q&sort&cursor` returns 24 + next cursor (keyset on `(players, id)`), max page size 48, hard rate limit per IP, `Cache-Control: s-maxage=60`.
Search: `q` over `lower(name)` trigram + game name + address prefix; require >= 2 chars; debounce 250 ms; results cap 24 + "see all" -> game page with `q`. Counts per facet computed with `GROUP BY` on the filtered set, only for the requested facet dims, capped, cached 60 s by (game,filters hash).
Ingest scaling: Steam fan-out 8 regions x up to `limit` (Valve caps ~5000 per call; regions branch uses 300): raise to 1000 per region for the big 6 games, keep `MAX_GAMES_PER_TICK`, daily budget = `callsRemaining` cap (2,000/day currently; the 30-game fan-out needs ~960/day at 4 passes: raise the cap to 3,000, still 3% of Valve's limit). Rows/game up to ~8k (rust). Estimated total 20-60k rows x ~600 B = 12-36 MB heap, +indexes ~3x (today 5,883 rows = 3.8 MB table: verified), negligible.
Prober scaling (verified constants): `PROBE_RATE_PER_SEC=10`, `ALIVE_REPROBE_MS=30 min`, `BATCH=450`, `CANDIDATE_LIMIT=4000`, 50 s tick budget. At 10/s one full pass over 40k rows = 67 min, but ALIVE rows need a pass every 30 min: capacity is ~18k rows/30 min. For 40k+ rows: (1) probe public-visible rows only (those that would render), (2) tier by interest: rows with players>0 or favourited/viewed every 30 min, empty rows every 3 h (they show "seen on the list" with no player count), (3) raise `PROBE_RATE_PER_SEC` to 25 on a dedicated probe box (NXEON_DIRECTORY_PROBE=1, not the primary; owner decision D6), per-IP/-subnet caps unchanged. Prober is currently OFF (all rows UNKNOWN): turning it on is the single highest-value trust change for "live" claims, and the list stays honest either way ("Seen on the list" vs "Checked").
Prune rules: external rows not seen by their source for 3 days drop from display (existing `lastSeenAt >= now-3d`), hard-delete after 30 days (new job; keep `DirectoryIngestRun`), DEAD rows re-checked daily, delete after 14 days DEAD; image prune weekly; stat samples 14 days; reports kept 1 year.
