## 1. Test Flight verdict honesty (fire-sword mb40f9b72699ef38d0d30c)
Root cause is NOT the verdict logic alone. plugin.yml registers `/firesword`; the model's summary.json listed `/fireswordmod give|list|params|reload|hud toggle`, so the flight's `help fireswordmod` check failed. Two defects: the owner was shown commands that do not exist, and gateVerdict deliberately excluded commands_registered ("optional", rcon checks are required:false), so verdict stayed "passed" with label "boot-tested".
- Service (autofix.reconcileCommands, wired in finish()): a listed usage root that is neither a declared command nor an alias is rewritten to the registered one (the only declared command when exactly one root is unknown, or the single declared name contained in / containing the label); also in howToUse; several candidates = never guessed (rec.commandUnresolved). Event "Corrected the command list: /fireswordmod -> /firesword".
- Portal gate: failed commands_registered = new verdict `passed_with_warnings`, label "boot-tested on Paper X, but none of its N listed command(s) registered on the test server (/a, ...)". Never "passed", never blocks install, not excluded from featuring (it did load). The check stays non-fatal only in the sense that it cannot make a flight "failed"; "optional" had no real use case (all labels come from the build's own command list), so no per-check optional flag was kept.
- Consumers updated: flightBadge (warn tone), flightLines, flightFailureOf (new `tone: failed|warning` banner "Some commands did not register in our test server" with Refine), project page, admin build page badge, eval score/passrate/matrix (boot counts as pass there), aggregates (ops/delivery pass rates) count it under "incomplete" (not inflated).

## 2. Creature not delivered (boss-minions mb6d31dce76454b984b83e)
Record: plan lanes texture/sound/creature/designBoss; assets.design + bosses + creature all on; events show only design JSON written (hollow_crown/scepter/king), 4 repairs (2 asset on the boss design, 2 compile in generated HollowKingBoss.java), no assets/creatures spec ever written, downgraded [] (nothing to downgrade, so nothing was reported). The creature section was appended anyway, the model (correctly following the designer rules) skipped it, and the lane was silently lost.
- Layer fix: textures.parseAssetsRequest switches creature OFF when design is on (note + `laneOff.creature` reason, persisted on rec.assets), so no creature prompt section and no wasted repairs. Plain (non-design) creature builds (fox, goblin) are unchanged.
- Never silent: new lanegaps.js compares plan lanes with what shipped (textures, sounds, creatures, datapacks, itemStates, designs) and emits `assetResult.laneGaps`, a warning, and a summary limitation: "The planned animated creature part was not delivered: <reason>. The build itself still works; ask for it in a change request or Refine to try again." Portal: assets sync carries laneGaps (also when it is the only asset signal), MbAssets.laneGaps, project page card "Planned but not delivered" (laneGapsOf).
- Not done: making a designer boss use a real creature model (would need a designer boss "model" field + compiler support). The planner could also stop planning creature next to designBoss (portal side), saving the user the expectation; owner decision.
- 5 attempts / $1.24: the repairs were boss-design asset problems and two compile errors in generated code, i.e. cost of the design lane, not of the creature.

## 4. Config schema warnings (13 food-potions, 8 economy-config)
Neither set was "keys the model forgot":
- food-potions 13 = perf.* read by the Nxeon-injected NxPerf watchdog (its keys are written to config.yml by Nxeon with their own comments).
- economy-config 8 = `accounts, balance, daily_earned, last_*` read from the mod's own data.yml via YamlConfiguration, plus `item`/`sell`/`name` (table columns of shop.items and a data field). Adding those to the Config Studio would create settings that do nothing.
Fix (lib/cyrus/config/verify.ts, regenerated services/modbuilder/config-spec.js): undeclared ignores files under /nxperf/, files that load their own YamlConfiguration without getConfig()/FileConfiguration/CyrusSettings, and declared table column keys. Unread detection unchanged. Plus the requested autofix (configs.js addUndeclared): a key the code really reads that exists in config.yml but not in the schema is added (type/limits/unit/group inferred from its default and comment by the existing inferSchema, label from the key), rec.configResult.autoAdded + one soft note. Test removes 3 recorded keys from the food-potions schema and checks they come back typed.
