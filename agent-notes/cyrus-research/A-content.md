# A. What a Paper plugin + server-pushed resource pack (+ datapack) can create on a VANILLA Java client

Date 2026-10-10. Web budget: 20 pages/searches used (several 404). Labels: VERIFIED (url) = opened; UNVERIFIED = memory/inference, re-check before building. Internal facts from E-versions.md / G-gaps.md (resource packs unsupported by installer; no pack hosting, no resource-pack server setting yet).

## 0. The enabling primitives (what exists today)
- **Item model definitions** (`assets/<ns>/items/*.json`, bound with the `item_model` component): types model/composite/condition/select/range_dispatch/special/empty; added 1.21.4, extended through 26.x. VERIFIED (https://minecraft.wiki/w/Items_model_definition). This replaced the old "overrides in the item model json" approach. Pre-1.21.4 versions (1.21.1) still need legacy `custom_model_data` int overrides: UNVERIFIED but well known; Cyrus supports 1.21.1 so the pack builder needs two emitters.
- **Data component API in Paper** (CUSTOM_MODEL_DATA, LORE, ENCHANTMENTS, RARITY, MAX_DAMAGE, EQUIPPABLE, GLIDER shown; item_model/food/consumable/weapon/tool/use_cooldown referenced). Docs warn "may experience breaking changes on version updates... backwards compatibility is not promised". VERIFIED (https://docs.papermc.io/paper/dev/data-component-api/). `@Experimental` removed in 26.3: VERIFIED internally (E-versions.md, papermc.io/news/26-3).
- **Registry mutation at bootstrap** (`RegistryEvents`, `compose()` / `entryAdd()`; example is enchantments; Paper plugin + `paper-plugin.yml` only; errors abort startup; compose fires after built-in/datapack content loads). VERIFIED (https://docs.papermc.io/paper/dev/registries/). Full list of writable registries: not determined.
- **Lifecycle API**: Brigadier commands, registry modification, datapack management at bootstrap. VERIFIED (https://docs.papermc.io/paper/dev/lifecycle/).
- **Datapacks shipped inside a plugin jar** (unzipped folder under resources, `DatapackRegistrar#discoverPack(URI,id)` in `DATAPACK_DISCOVERY`; pack name `<Plugin>/<id>`; discovery ignores enabled state). VERIFIED (https://docs.papermc.io/paper/dev/lifecycle/datapacks/). Runtime reload not documented there.
- **Pack format numbers** per version: see E-versions.md (VERIFIED minecraft.wiki/w/Pack_format). 26.x client needs correct `min_format/max_format`; current `packFormatFor` is wrong for 26.x.
- **Server-pushed pack**: `resource-pack` + sha1 in server.properties or Paper `Player#setResourcePack`; players get the accept prompt, no manual download. UNVERIFIED here (standard behaviour); Nxeon must host the zip over HTTPS (G-gaps section d).

## 2. Client-mod-only list (cannot be done on a vanilla client)
- New block types with arbitrary properties, new entity types with native models/animations, true custom blocks beyond the reusable-state pool.
- Arbitrary HUD widgets/GUI screens with real controls and free layout (Dialog API gives only form-like screens).
- Custom keybinds, mouse capture, camera control, client-side prediction (smooth gun recoil).
- New dimension sky/cloud/fog *renderers*; custom shaders that need new vertex formats; post-processing outside the shipped pipeline mechanism (UNVERIFIED how much `post_effect`/core shaders allow on 26.x).
- Anything requiring new client code paths (new GUI sliders, minimap, custom render of player model).
Fabric/NeoForge client-mod route: out of scope for Cyrus today; Nxeon would need to ship players a client mod pack = adoption friction.

Everything else (items, blocks, HUD glyph, pack builder, menus) should be a small **Cyrus runtime library** owned by Nxeon, because Cyrus-generated plugins are compiled against a frozen classpath and need a stable, versioned helper API anyway.

## 4. Ranked build order (value vs effort)
1. **Pack hosting + server-pushed pack + correct per-version pack_format** (S-M). Unblocks everything; installer currently marks packs unsupported.
2. **Items with custom art** via `item_model`/CMD, food/tool/weapon/armor components, recipes, sounds (M). Texture Studio output already exists in `lib/cyrus/textures`; biggest "wow per effort"; weapons/guns high AI reliability.
3. **Abilities/projectiles/bosses/commands/enchant/advancements** with vanilla-only assets (S, mostly prompt + sheet work).
4. **Custom mobs on BetterModel** (L): bbmodel emitter from Texture Studio spec, 1.21.4+ only, multi-sound set. Highest marketing value; heavy generation risk.
5. **Glyph-based HUD + GUI menus helper lib** (M): fonts/negative-space helper, Dialog where available; no core shaders.
6. **Datapack studio** for biomes/structures/enchants (L, see A2).
7. **Custom blocks/machines** (L): state-pool allocator + display-entity furniture; maintenance-heavy.
8. **Core-shader effects** (L, last or never): fragile across 26.x and client mods.

## 5. Gaps / not determined
