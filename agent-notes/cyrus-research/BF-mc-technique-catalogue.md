# BF: Minecraft technique catalogue for Cyrus (2026-10-12)

Companion data: `BF-mc-techniques.json` (156 de-duplicated techniques; 38 covered, 41 partial, 77 missing; labels V 132, V-s 23, U 1).

Labels. **V** = verified by me this session in the repo, the 386-mod corpus (class-file constant-pool census in `_reference-mods/analysis/per_item.jsonl`, zip listings, `pack.mcmeta` key names) or in cyrus-rc2 (grep with the recipe in each `evidence` field). **V-s** = second-hand from a note or skill (universal-modder, MJP, Jahrome907, BA/BB/BD). **U** = memory/unverified. No JDK on this box, so no `javap` was run by me: Paper API claims are V only in the sense "a real plugin's compiled class references this symbol" or "Cyrus's own javap-built sheet says so"; each fact in section (c) therefore still needs the 4-jar javap check before it goes into a sheet. Corpus content was inspected structurally only (class/method names, JSON key names, file-name lists); no code or file contents were copied, and GPL/ARR projects are described in my own words.

## (a) One-page summary

* Cyrus is already far ahead of the sources on the Paper API basics. The four version sheets, 33 failure rules, 85 coverage archetypes, 65 golden plugins, the designer (items/menus/quests/bosses/HUD/motion), the datapack emitters (recipe, loot, advancement, tag, function, enchantment, damage_type, jukebox_song, predicate, item_modifier, plus an own-namespace worldgen set) and the note-block/armor generators already cover the techniques in MJP and Jahrome907. Their pack-format table matches `lib/cyrus/versions/registry.json` exactly (DP 48/61/81/94.1, RP 34/46/64/75.0).
* The remaining value is in three places: (1) **real-plugin behaviours that never reached the sheets** (about 40 Paper events and a dozen Player/World methods used by 5-60 of the 173 top plugins but absent from `sheets/1.21.11.md`); (2) **whole archetypes with big download counts and zero Cyrus text**: vein miner/tree capitator (93M downloads), pick-up-a-mob items (680k/500k/263k), crates, combat tag, skyblock/oneblock, map images, dynamic lights, lifesteal; (3) **test-method gaps** from the universal-modder field notes: the stress bot sets creative mode (verified at `stress-bot.js:80`), so mob/boss checks can give false greens; no RCON ore-count probe, no mutant self-check, no `/tick freeze` timing.
* universal-modder is mostly Fabric/NeoForge/Forge client-mod material and says almost nothing about Paper; of its 11 skills only `mod-any-game/references/engines/minecraft.md` and two lines elsewhere mention Minecraft. MJP-Paper-Skills (15 Paper + 16 NMS skills) is high quality and mostly confirms Cyrus rules; its unique contributions are combat tag, per-player visual effects, disposable worlds, dialog pitfalls and the Hook/Bridge/Port soft-dependency split. Jahrome907 contributes the version metadata table (agrees with Cyrus), the CMD-strings vs numbers distinction and the "no supported core-shader override" claim (which conflicts with BB). OGMatrix is an MCP code server (no prose to extract); gamedev-skills has no Minecraft content.
* Deliberate exclusions to keep honest: Brigadier/paper-plugin.yml/Folia/NMS/PacketEvents/networking/Vault-PlaceholderAPI-WorldGuard hooks are all rejected by Cyrus hard rules (rules r1-r10, `failure-rules.json`). Many of the top real plugins depend on exactly these (corpus: 24% Brigadier, 42% Folia, 62% PlaceholderAPI softdepend), which is why Cyrus must keep saying "limitations" instead of silently dropping them.

## (e) Conflicts and traps

1. **Core shaders**: BB says unsupported but working (V wiki); Jahrome says vanilla gives no supported override; corpus shows 4/43 packs ship them (glint, text, lightmap). Format changes at 1.21.2, 1.21.5, 1.21.6 and 26.x (V-s BB). Treat as per-band, client-verified, Iris/OptiFine may ignore.
2. **Dialog timeline**: vanilla 1.21.6; Paper API 1.21.7 (MJP) vs Cyrus javap "present on 1.21.8, absent on 1.21.4"; 1.21.6/7 are not in Cyrus's version set, so nothing to fix, but do not write "from 1.21.6" in a sheet.
3. **Note-block state counts**: BB 16 x 25 x 2 = 800; Cyrus reserves the 7 mob-head instruments = 350 states and its data generator lists 23 instruments on 1.21.x (16 + 7) and 27 on 26.2. Both are right for what they count; the safe reserved set is the mob-head one because vanilla only reaches it with a head above.
4. **Macros**: Jahrome's datapack skill teaches `$(arg)` macros; Cyrus's function checker refuses macro lines and `function ... with` (`functions.ts:151,258`) because commands cannot be statically checked. Keep refusing; add an eval refusal case.
5. **Commands**: MJP/Jahrome push Brigadier and `paper-plugin.yml`; Cyrus accepts plugin.yml only. 24% of corpus plugins use Brigadier, 10% paper-plugin.yml. MJP's own note: `getPlayerOrThrow()` exists only on 26.2, not 1.21.11.
6. **Item model data**: Jahrome's own example uses `meta.setCustomModelData(1001)` for a Magic Wand, which on 1.21.4+ packs maps to floats not strings; on current jars `setCustomModelData(Integer)` is deprecated but compiles (Cyrus sheet). Mixing the legacy numeric override and the 1.21.4 `items/` selector silently shows nothing.
7. **Equipment asset paths**: 1.21.2 used `models/equipment`, 1.21.4+ uses `assets/<ns>/equipment` (V-s BB); 1.21.1 has no equippable component (Cyrus falls back to dyed leather).
8. **Datapack folder names**: 1.21 renamed to singular (`function`, `recipe`, `loot_table`, `advancement`); 13 of 141 corpus packs ship both spellings for older versions. Cyrus emits singular only.
9. **Pack format for 1.21.9+**: `min_format`/`max_format` arrays, no decimals; a legacy range must keep `pack_format` and `supported_formats`; overlays use `min_inclusive`/`max_inclusive` objects in real packs (V corpus) and `formats` in older ones.
10. **Registry vs enum**: Attribute and Sound are enums on 1.21.1 and interfaces from 1.21.4; Villager.Profession/Type and Cat.Type interfaces on all. Already in rules; MJP/Jahrome examples written for 26.x use the interface style and would not compile on 1.21.1.
11. **Worldgen names**: Jahrome says 26.3 uses `worldgen/feature` and moved biome spawn costs to environment attributes, 1.21.11 already uses attributes for sky (Cyrus `worldgen/versions.ts`); `configured_feature` remains correct on all four supported versions.
12. **Creative-mode test false greens** (verified in stress-bot.js:80; mechanism V-s): mob targeting skips creative/spectator players; GameTest `makeMockServerPlayerInLevel()` is creative (client-mod lane only).
13. **Unloaded-chunk height query** returns the world minimum (V-s two sources); do not build a platform on it.
14. **Effects silently dropped** (virtual border, night vision, personal time) by world change, respawn, milk, `/effect clear`: reapply from a desired-state object (V-s MJP).
15. **Orphan entities**: display/seat/Interaction entities survive crashes; tag them and sweep on chunk load. Entities spawned where no player is unload at once on 1.21.11 (Cyrus sheet).
16. **Licences**: Oraxen (custom), CraftEngine (GPL-3), EliteMobs/Skript/Grim/WorldEdit/spark (GPL), PackSquash (AGPL), Blockbench (GPL) are reference-only. Corpus plugins are third-party: describe, never copy. BetterModel (MIT) is the only rig engine in the lane.
17. **Bedrock**: Java packs are not auto-converted; glyph fonts show raw codepoints; Geyser custom blocks are "not very stable" (V-s BB); Cyrus only detects Geyser/Floodgate.
18. **Version gaps in Cyrus sheets**: no 1.21.5-1.21.7, 1.21.9, 1.21.10 jars, so any API introduced there (TooltipDisplay 1.21.5, Mannequin 1.21.9, Dialog 1.21.6/7) is only checkable at the four supported versions.
