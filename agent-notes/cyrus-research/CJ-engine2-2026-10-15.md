## 1. Version-aware datapack / resource-pack validator (card 9): DONE, flag `MB_SPYGLASS`

**Verdict: Spyglass runs headless and offline, so it is wired in (no fallback structural checks needed).** Spike facts:
- `@spyglassmc/core` 0.4.57 + `java-edition` 0.3.70 + `mcdoc` 0.3.61, all MIT, 18 MB installed. Drives fine from Node 22 with `Project` + a stub file watcher (without the watcher the pack's own resources are not declared and every own-namespace reference is a false "Cannot find" warning: found and fixed in the spike).
- Runtime needs per-version data from `api.spyglassmc.com` (block_states, commands, registries, vanilla-data tarball, optional vanilla-assets-tiny) plus the vanilla-mcdoc tarball. All are fetched once at image build and sha256-pinned; the child process answers every request from the local files, so runtime is fully offline.
- Cost: about 13 s per run (8 s with a persistent symbol cache `MB_SPYGLASS_CACHE`), memoised by content so one build pays once.

- Mutation test: a 1.20-style recipe `result.item`, an extra key, a loot entry with a non-existent item, and an invalid function line are all caught, with line numbers and hints.

## 2. Release-day API diff (card 15): DONE

`node scripts/cyrus/api-diff.js --from A --to B --out report.md --json report.json` (`scripts/cyrus/api-diff.js`, test `test/cyrus-api-diff.test.ts`). Method: javap on the public API of both versions (the structure round's `parseJavap`), diff of types / constants / fields / methods / return types / newly `@Deprecated` (javap -v, for touched and used types), in-type rename detection (prefix drop, word-set, edit distance), overload-only removals separated, then impact analysis against the sheets, failure rules, prompts, autofix and the golden plugins' used symbols. Output: markdown + JSON with `candidateRules[]` shaped like failure-rules entries (marked `candidate: true`, never auto-merged).

Why not japicmp: it needs a JDK and the same jars, and its output (class-level binary compatibility) would still have to be mapped to our symbol use; javap + the member-index parser gives the mapping directly. japicmp can still be run by hand as a second opinion. paper-api is GPL-3.0: only names leave the jars, as in the sheets.

Jars used on node-2: 1.21.8 and 1.21.11 `paper-api-*.jar` from `/tank/nxeon-build/tmp/mc-coverage/cp`; 26.1.2 and 26.2 `paper-api-26.x.build.N-stable.jar` downloaded from repo.papermc.io (2.9 MB each; no jar for 26.x existed on this host; the server jars exist under testflight/paper but include implementation, so the API jars are cleaner). Reports (markdown + JSON) are stored with this note in `CJ-engine2-api-diff/`.

RESULTS_TABLE

Highlights that matter for Cyrus:
- 1.21.8 -> 1.21.11: all `GameRule` constants newly deprecated (the known `gamerule-constants-1-21-11` class: the diff would have found it on release day, and flags `mc-events` golden), `Material.CHAIN` removed (hits sheets 1.21.1/1.21.4/1.21.8 and a failure rule: still named there, needs a version scope check), `WorldCreator.keepSpawnInMemory` removed, `Bukkit/Server.getDataPackManager` + `org.bukkit.packs.*` removed, `EnchantmentWrapper` / `PotionEffectTypeWrapper` legacy methods removed.
- 1.21.11 -> 26.1.2: small: `TimeSkipEvent.getSkipReason/getSkipAmount` removed, `DamageResistant.damageResistant(TagKey)` + `BlocksAttacks.bypassedBy` return type TagKey -> RegistryKeySet, `Breedable` age-lock methods, `PlayerInteractAtEntityEvent` handler-list methods; `WorldCreator` deprecated (hits golden mc-worlds); many `Tag.*` constants deprecated.

## 4. Method adoption: DONE (flags default off; evidence and MODLOG are read-only views)

(a) **Evidence levels** `lib/cyrus/evidence/levels.ts`: `static < synthetic < booted < behaviour < client`. Rules: a rung counts only with evidence; queued/running/not_run never count; a failed rung is shown as failed and named in the headline ("Loaded in a simulated server only ... A Test Flight check FAILED"); `client` is reachable only by an explicit client record (nothing sets it today, so the portal says "no game client was used"). Shown on the project page ("How far it was verified": the rung ladder, each rung reached/failed/not run/not available, and what would raise it) and carried on every MODLOG entry. Derived from existing records (pre-flight verdict, StoredFlight checks, functional oracle, playtest), so no schema change and the service needs no change.

(b) **Publish-check lint** `lib/cyrus/safety/publish-check.ts`, env `CYRUS_PUBLISH_CHECK=off|warn|enforce` (default off, registered in the admin flags list). Checks: commands exist (ledger-dropped/regressed commands = error; advertised-but-undeclared = warn), hard dependencies resolvable (BetterModel and the pack loader are; Vault/LuckPerms-style hard depends = error, soft = info), no placeholder text in title/tagline/description/commands/config/summary (TODO, lorem ipsum, "your text here", example.com ...), licence line and credit lines when credit-requiring material is used, config keys documented, duplicate namespace (error) / plugin name (warn) / command clash (info). Wired into `saveModListing` when visibility becomes PUBLIC: warn returns the report with the save, enforce refuses only on error-severity findings. A lint, not legal advice. Not yet fed: plugin.yml depend lists (the build result does not carry them; pass `depends` once the service exposes it) and "other listed mods of the creator" (`others`).

(c) **MODLOG** `lib/cyrus/modlog/modlog.ts` shown in the studio Notes tab ("Change log", newest first): per build what was asked, why (first build or owner change request), what changed, ledger added/regressed/dropped/lane flips, notices, evidence level. Append-only by construction: derived from the immutable build rows, so a new build appends one entry and older entries cannot change (tested). It is fed by `result.ledger` that `services/modbuilder/ledger.js` already writes.

Not adopted on purpose: "suspect the oracle" is a triage procedure, not code; it belongs in agent briefs (BX Q7) and was left as is.
