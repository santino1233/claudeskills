## Honest limits
- Steam-list ingest was only tested against a fixture shaped like the documented response (parser + dedupe unit tests); never called the real API.
- Rust join/leave regexes (lib/game-control.ts GAME_LOG_TRACKING.rust) are from Facepunch's documented output + community parsers, NOT verified on a
  live Nxeon Rust server. Rust logs are chatty (500-line tail per sweep): events can be missed.
- Console-join copy (Palworld, Valheim) is grounded in this repo's own ticket-derived comments; Valheim "find by name / join code" and the
  `join code NNN` log line are from memory of the crossplay behaviour, never tested on a console. ARK/other games deliberately get no card.
- World import: classifier + path-safety unit-tested; the SFTP placement/rollback + extractArchive hand-off were NOT run against a real VM
  (sandbox simulation only at best). Valheim folder-save format (.fwl2/.db2/.chunk markers) is inferred from lib/game-control.ts comments.
  MC replaces the folder named by server.properties level-name (default `world`); old one renamed `.pre-import-<stamp>`. Not a wizard step in the
  ORDER flow on purpose: the VM does not exist at order time, so it is a panel action (Backups tab).
- Region transfer: request only. Estimate bands (30-60 min / 1-2 h / 2-6 h) are derived from the two manual transfers (tickets 1 and 9), labelled as
  an estimate. VM move engine untouched and still NO-GO for real customers.
- Third-party "submission helpers" are a copy-paste kit (name, address, blurb + links to GameMonitoring and serverlist.gg from the item text); nothing is
  submitted automatically and the listing forms were not checked.
- Core Keeper has no Steam master-list presence (not in VALVE_APPIDS); its page lists Nxeon-hosted opt-in servers only.
