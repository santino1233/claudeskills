The owner's vision (verbatim in CONTEXT.md): Cyrus is a **community**. A Cyrus project can be opened in **NxLabs**, where the creator changes the title, adds photos and fully customises the mod page. Other people can **build off** a mod, can **load other community Cyrus mods directly into their own Cyrus**, and **their changes go under "Community versions" on the original mod's page**. "I really want you to expand on this community idea."

Build:
1. **Open in NxLabs**: from a Cyrus mod, one click to its listing; an owner edit mode there for title, icon/banner, **photo gallery**, long description (markdown, reuse the existing renderer/sanitiser), tags, links, changelog, visibility. Own the storage and `saveModListing(projectIdOrBuildId, input)` + the shared type from `lib/cyrus/listing.ts` (the routing agent defines `ModListingInput`; if not on your branch yet, define a compatible type in `lib/cyrus-mods/listing.ts` and note it).
2. **Remix / build on**: authors choose whether remixing is allowed (sensible default, documented), with credit ("Remixed from X by Y") preserved down the chain. "Remix in my Cyrus" creates a new project seeded with the source and prompt history. The remix's published versions appear under **Community versions** on the ORIGINAL page (a list with author, base version, summary, diff view using `lib/cyrus/diff.ts`, test status); the original author can pin/endorse one. Re-scan remixed code through the existing safety scanner before any build.
3. **Load community mods into my Cyrus**: a library/"Add to my Cyrus" action puts a community mod on my map as a read-only branch node (installable, remixable) without copying it until I remix.
4. **Expand the community**, in order of value, implementing the core and leaving a clear roadmap for the rest: stars/likes; creator profiles; collections ("modpacks"); a computed, objective **Community-tested** status that earns the laurel badge (define criteria from real data: installs, ratings, no open BUG, works on the current game version; never manual or fake); "works with version X" compatibility tags; changelogs; fork graph view; report/moderation hooks (reuse the existing report flow). Every number shown is real. Use `BuiltWithCyrusBadge` from the studio-ui agent (`components/cyrus/brand/`); if absent when you need it, create it under `components/cyrus-mods/` with the same props and note the duplicate for the merge.
5. **Schema**: you own Prisma additions for all of this: additive only, new tables or nullable/defaulted columns, no new unique constraint on populated tables, placed at the end of the file with comments. Include a migration note and the exact `db push` expectation.
