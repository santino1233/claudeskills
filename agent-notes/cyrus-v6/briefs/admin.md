## Scope: the Cyrus admin portal (operating the product)
Nobody owns the staff side of Cyrus yet, and the other agents are adding things staff must be able to see and control. Read the existing admin area first (`app/admin/*`, `lib/admin-*`, the role/area gating `requireArea`, the existing Cyrus admin bits if any: `grep -rn "cyrus" app/admin lib -il`), the token economy (`lib/cyrus/tokens/*`, `ECONOMY.md`), the mods ecosystem (`lib/cyrus-mods/*`, reports/moderation in `lib/actions-cyrus-mods.ts`), the build service and `lib/modbuilder/*`, and the other agents' briefs in `/root/agent-notes/cyrus-v6/briefs/` (community, lifecycle, capabilities, library, game agents, routing) so your admin screens plug into what they build (read their branches `feature/cyrus-v6-*` as they land; do not edit their files, add admin-only pages and small adapters).

Build `/admin/cyrus` (role-gated like the other admin areas, dark and light, responsive), with tabs:
1. **Overview/health**: builds per day, success/fail/refused rates by game and model, average and p95 build time, queue depth, build-service health (reuse the service `/health`), token spend vs customer tokens charged (margin by model, from the usage records in service 0.5), errors needing attention. Real data only; honest empty states.
2. **Builds**: searchable table (user, game, version, model, status, cost, tokens charged, duration, refused reason), build detail (prompt, stages, events, files, safety findings, usage per stage), actions: cancel a stuck build, refund tokens through the existing economy path (audited; never touch money outside it), re-run.
3. **Users and tokens**: per-user balance, plan, grants, ledger, comps (the owner comped tierOverride/tokens earlier: expose that action audited), abuse flags and rate limits.
4. **Games and models**: the game status table (live/soon/disabled) with a safe toggle per game as a setting (`cyrus_game_<id>_status`; today it is hard-coded in `lib/cyrus/games.ts`: add a settings-backed override with the file as default), readiness checklists from the game agents' `READINESS.md`, model tier mapping view (Katara/Saka/Yakko -> underlying model, costs) and the efficiency knobs documented in `docs/DOCUMENTATION.md` (read-only display of what the service is configured with; do NOT change the build VM).
5. **Community moderation**: the reports queue (exists in `lib/actions-cyrus-mods.ts`), hidden posts, remix disputes, takedown actions, creator suspensions, audit log; the **networking review queue** (mods that declare network hosts once the capabilities agent lands; until then a stub reading `lib/cyrus/capabilities.ts` if present) with approve/block and a global kill switch for `cyrus_mod_networking_enabled`.
6. **Library and safety**: pattern library coverage and verification status (read `lib/cyrus/library/*` when it lands), recent safety-scan blocks, compat-watch results (lifecycle agent's `cyrus_compat_watch_enabled` sweep dry-run output).
7. **Audit log and settings**: one list of every admin action taken here (who, what, when, before/after), plus the Cyrus-related settings in one place with descriptions and safe defaults.

Rules: every write is permission-checked, audited and reversible where possible; no direct DB edits to money outside the economy module; no secrets shown; never name a third-party infrastructure provider in customer-facing text (admin-only screens may). Add a short admin guide to `docs/DOCUMENTATION.md`. Verify through the real route on node-2 with a seeded throwaway DB (fake data clearly labelled), screenshots of every tab (dark and light, 1440 and 390), `devhost tsc` clean, tests for pure logic (margin maths, filters, permission checks). End with a short report listing what each tab shows today versus what it needs from the other agents' merges.
