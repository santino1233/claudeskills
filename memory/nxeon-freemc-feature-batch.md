Follows [[nxeon-freemc-dashboard]] (the original 5-tab dashboard) and [[nxeon-free-minecraft-tier]] (the infra). User asked for "all the game modes" (was 4), then rapid-fire added: inventory editing, a game-mode section in Overview asked at setup, mod menus, player roles with command permissions, and a public server directory with per-server marketing pages — all in one session, via "run all the agents, don't stop until it's all done."

**1. Game mode library — 12 total, all live-verified against real freemc-host (not just researched):**
Vanilla/Creative/Hardcore/Peaceful (properties-only, pre-existing) + SkyBlock, Prison, Towny, Parkour, Anarchy, Lifesteal SMP, Missile Wars, Survival Games (all plugins-kind, `lib/free-minecraft-control.ts`). `FREEMC_PLUGIN_MC_VERSION="26.1.2"` pinned on every plugin container. **LuckPerms now bundled on every plugins-kind preset** (added specifically as the roles feature's foundation).

Real bugs found only by live-testing, not research: AntiCrasher for Anarchy was a Fabric mod, not Paper — wrong loader entirely, dropped. MissileWars' pinned Hangar URL had the wrong author path (404) and doesn't declare its hard WorldEdit dependency — fixed URL + added `worldedit` to its env. SkyBlock OOM'd at JVM ratio 0.85 (fixed earlier at 0.7 for all plugin presets). The create-server form (`components/customer/FreeMinecraftPanel.tsx`) now asks which mode to start with instead of always defaulting to Vanilla.

**2. Mod menu (`lib/freemc-mod-catalog.ts`, `lib/actions-freemc-mods.ts`, `components/customer/freemc/ModsTab.tsx`):** 16 extra plugins on top of a preset's own, from a fixed allowlist only (never free-text — a plugin slug is code on shared infra). All 16 live-boot-tested. 3 candidates dropped after live-testing found real problems: `grimac` (alpha-only Modrinth releases, itzg's installer rejects non-release by default, **took the whole container down**), `auction-house-plugin` (hard `UnknownDependencyException: Vault`, crashes), `crazyauctions` (same missing-Vault issue, soft-fails to a dead no-op feature).

**3. Player inventory editor (`lib/minecraft-items.ts`, `lib/minecraft-slots.ts`, `lib/actions-freemc-inventory.ts`, `components/customer/freemc/InventoryEditor.tsx`):** Vanilla RCON has no inventory-READ command — this is a write-only "set this slot to become X" tool, explicit in the UI copy, not a live view. **Correction found via live testing:** the slot vocabulary is `inventory.0-26` (27) **plus** `hotbar.0-8` (9) as two separate namespaces = 36 total — NOT a single `inventory.0-35` range as commonly assumed. `inventory.27`/`hotbar.9` both error `"Unknown slot"`. 392-item curated catalog. Every edit re-verifies the target player is online at submit time (never trusts the client dropdown).

**4. Roles & command permissions (`lib/freemc-command-catalog.ts`, `lib/actions-freemc-roles.ts`, `components/customer/freemc/RolesTab.tsx`) — the most technically interesting piece:**
- **LuckPerms' RCON text responses are silently discarded** — every `/lp ...` command executes correctly (verified by reading LP's own storage back) but the response never reaches the RCON socket (LP dispatches on its own async thread pool; Bukkit's RCON feedback collector has already torn down by the time it replies, and it isn't logged to console either). Confirmed LP-specific — vanilla `list`/`seed` and Paper's `/plugins` return real RCON text fine on the same container.
- **Fix:** mutations still fire over RCON (fire-and-forget); every READ (roles, their permissions, their members) parses LuckPerms' own `yaml-storage/groups/*.yml` and `yaml-storage/users/*.yml` files directly via SSH `cat` — required switching LP off its H2 default to `yaml` storage (H2 isn't parseable without a JDBC driver), done idempotently by `ensureLuckPermsReady()`.
- **Second bug:** LuckPerms' default `use-server-uuid-cache: false` makes `/lp user <name> parent add <group>` silently no-op for a player who's never joined — no user file is ever created. Fixed by flipping that config key; verified the created file's UUID matches Node's own offline-UUID computation (`MD5("OfflinePlayer:"+name)`, patched to v3) exactly, so role assignment works by username alone.
- **Catalog correction:** the assumed EssentialsX convention `essentials.command.<cmd>` is wrong — the real convention (confirmed by extracting the jar's plugin.yml/string constants) is `essentials.<cmd>` (e.g. `essentials.give`), with one irregular case: `/tp` → `essentials.teleport`, not `essentials.tp`.
- **Fundamental, honestly-reported limitation:** RCON always runs as a permission-bypassing console sender by Bukkit design, so no RCON-issued command can ever be observed being denied — true in-game deny-testing wasn't possible (no MC client library available in this environment). Only available on plugin-based presets (`kind==="plugins"`) — properties-only presets show a "not available" message.

**5. Public server directory (`lib/actions-freemc-public.ts`, `components/customer/freemc/PublicListingCard.tsx`, `app/(marketing)/servers/page.tsx`, `app/(marketing)/servers/[subdomain]/page.tsx`):** Opt-in (`isPublic` off by default) + `publicTagline`/`publicDescription`. `/servers` lists public+READY servers (capped 48, documented not silent). `/servers/[subdomain]` hard-`notFound()`s unless `isPublic && status==="READY"` — a private server's existence/address is never inferable, checked identically in `generateMetadata` and the page body. Sitemap (`app/sitemap.ts`) gained the static `/servers` entry plus one dynamic entry per public server, following the existing blog-post pattern.

**Orchestration lesson:** `Agent`'s `isolation:"worktree"` failed outright here — "not in a git repository" — because the harness's own cwd (`/root`) isn't a git repo, even though the target repo (`/opt/nxeon`) is elsewhere on disk. Worked around it by having each agent explicitly `git worktree add` itself in its own prompt instead of relying on the tool's automatic isolation. All 4 agents were told to build self-contained NEW files only (never touch `FreeMcDashboard.tsx`/`actions-free-minecraft.ts`/`schema.prisma`) so their work merged with zero conflicts; wiring the 4 new tabs into the dashboard was done by hand afterward in one dedicated `feature/freemc-integrate` worktree.

**Integration bug caught only at final full-build time (not per-agent, since each agent only builds its own new files in isolation):** `ModsTab.tsx` (a `"use client"` component) imported `FREEMC_PRESETS` directly from `lib/free-minecraft-control.ts`, which transitively imports `lib/ssh-exec.ts` (the `ssh2` package) — broke webpack trying to bundle Node's `fs`/`child_process` for the browser. Fixed by passing the one boolean actually needed (`runsPlugins`) down as a prop instead of importing the server-only module client-side. **Lesson: a per-agent isolated build passing doesn't guarantee the FULL integrated build passes — always run one final `npm run build` after wiring everything together, not just after each piece.**
