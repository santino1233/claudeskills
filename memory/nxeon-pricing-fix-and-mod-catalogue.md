Two pieces shipped, both live + staging synced.

**1. Pricing page capitalization fix (commit 8524b11).** User sent an annotated screenshot of `/pricing`'s Game Servers tab circling the game-pill row: half the pills read as raw lowercase slugs ("sdtd", "vrising", "enshrouded", "gmod", "theforest", "sonsoftheforest", "bedrock", "conan", "unturned", "factorio", "ark", "satisfactory", "projectzomboid"). This was the SAME bug class as [[nxeon-game-servers-batch]]'s `GAME_META` fix from 2026-08-23 (only 6/19 games had display names) — except that fix consolidated the deploy wizard and games list into the shared `GAME_DISPLAY` map (`lib/games.ts`) but MISSED this third call site: `app/(marketing)/pricing/page.tsx` had its own separate local `GAME_NAME` map, also only 6/19. Fixed by swapping it for the shared `GAME_DISPLAY`. **Lesson: when consolidating a duplicated map into a single source of truth, grep for ALL local copies before considering the bug closed — `grep -rn "GAME_NAME\|GAME_META" --include=*.tsx` would have caught this the first time.** Verified via Playwright (desktop + mobile) that once capitalization was fixed, the row already looked clean — the user's "clean this up" ask turned out to BE the capitalization fix, not a separate layout problem.

**2. `/game-servers/mods` catalogue page (commit 61d87e7).** User asked for a "mod menu catalogue page for all of the games... go all out on the design" (for game servers, confirmed via a follow-up one-liner). Researched what mod capability the platform actually has FIRST (`lib/actions-game-control.ts`, `lib/game-control.ts`) — confirmed there is NO one-click mod installer, only full SFTP/file-manager/console/RCON access — so the page is deliberately honest: it frames the pitch as "nothing artificially blocked," not a feature that doesn't exist. New `lib/game-mods.ts` documents the REAL modding platform per family (Forge/Fabric/Paper for Minecraft, Oxide/uMod for Rust, BepInEx for Valheim/V Rising/The Forest/Sons of the Forest, Steam Workshop for ARK/GMod/Zomboid/Conan, tModLoader for Terraria, Factorio's own native mod portal, etc.) — same "single source of truth per family" pattern as `GAME_DISPLAY`/`GAME_ART_SLUG`, reusing `GameCoverTile` for the poster art so it's visually consistent with the rest of the site with zero new asset work. Linked from the game-servers page's existing "Full control panel" section (which already mentioned "manage mods and configs") and the footer's Game servers column; added to `app/sitemap.ts`.

**Playwright gotcha hit again:** a first `fullPage: true` screenshot showed enormous blank gaps between every section — looked like a serious rendering bug. Was actually `Reveal`'s (fade-in-on-scroll, IntersectionObserver-based) content never triggering under Playwright's synthetic full-page capture, which resizes the viewport instantly rather than actually scrolling. Re-verified by scrolling the page down in real increments (`window.scrollTo` in a loop with waits) before capturing — content rendered perfectly. **Lesson: this component is used site-wide; a `fullPage: true` Playwright screenshot of ANY page using `Reveal` will show this same false-blank artifact — always scroll incrementally first, don't trust a single `fullPage` shot as evidence of a missing-content bug.**

Both verified live post-deploy (curl 200s, links present in served HTML) before wrapping up.

Rewrote the hero, "how it works" steps, and FAQ to describe both paths (one-click store for those 5, SFTP for the other 14), and added a green "One-click Mod Store" badge to those 5 cards in the grid. **Lesson: my original research only grepped `lib/actions-game-control.ts`/`lib/game-control.ts` for "mod" — missed the entirely separate `lib/actions-mods.ts` file. When claiming a platform does/doesn't have a capability, grep broadly (`-l "mod" lib/actions-*.ts`) before writing copy, not just the file that seems most obviously relevant.**
