Shared hosting = many customers isolated on ONE box (jailed unix user + per-user PHP-FPM pool + disk quota + name-based nginx vhost + scoped DB + mail), no per-customer VM. The entry tier below VPS; big acquisition lever paired with the [[nxeon-migration-reliability]] engine ("move your site here free"). Chosen model (user-approved): **in-house per-user FPM pools (Hestia-style)**, reusing the existing control-panel primitives — NOT CloudLinux/cPanel.

**DNS model (user asked):** all accounts on a node share ONE public IP. nginx routes by Host header (name-based vhosts); customer points an **A record at `HostingNode.publicIp`** (surfaced as the account's pointTo). Per-domain SSL via **SNI** on the one IP. Optionally offer nameservers later.

**QUOTA GOTCHA (cost hours — remember):** stock Ubuntu cloud image can't enforce ext4 quota out of the box — (a) the `qfmt_v2` kernel module lives in `linux-modules-extra-$(uname -r)` which the minimal image omits (→ ext4_enable_quotas fails ESRCH, silent no-op), and (b) enabling the ext4 quota FEATURE on the mounted root fs is impossible live and leaves quota inodes uninitialised. SOLUTION (now in onboard-hosting-node.sh): install linux-modules-extra + back /home with a **dedicated loopback ext4 created via `mkfs.ext4 -O quota`** (inodes init correctly), mounted by a **systemd oneshot** `nxeon-hosting-home.service` (NOT fstab — fstab loop+quota mounts too early and drops quota every reboot).

**Before adding more nodes:** the node-creation itself must set up that loopback (the onboard script does it now). fail2ban ✓ + ModSecurity ✓ loaded; confirm ClamAV nightly + `modsecurity on;` in nginx http block per box.
